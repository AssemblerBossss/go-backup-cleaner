# v1: CLI + YAML-конфиг + правила на директорию + исключение по расширению

Документ описывает, что и где менять в коде, чтобы превратить библиотеку
`gobackupcleaner` в CLI-инструмент с YAML-конфигом, поддержкой нескольких
директорий (каждая со своими правилами) и исключением файлов по расширению.

Код здесь — не готовый патч, а точное описание изменений (файл, место,
сигнатура, фрагмент) для ручного внедрения.

---

## 0. Общая схема

```
gobackupcleaner (корневой пакет, package gobackupcleaner)
├── config.go        <- добавить ExcludeExtensions, DryRun
├── scanner.go        <- учитывать исключения при сканировании
├── deleter.go         <- учитывать исключения и DryRun при удалении
├── errors.go          <- (опционально) новая ошибка валидации
│
└── cmd/backup-cleaner/          <- НОВАЯ директория, отдельный package main
    ├── main.go        <- точка входа CLI, флаги, запуск по targets
    ├── config.go        <- YAML-структуры, загрузка, маппинг в CleaningConfig
    └── config_test.go   <- тесты загрузки YAML (опционально)
```

Важно: YAML-парсер (`gopkg.in/yaml.v3`) подключается только в
`cmd/backup-cleaner`, а не в корневой пакет. Так библиотека
`gobackupcleaner` остаётся зависимой только от stdlib, и тот, кто
импортирует её напрямую (не через CLI), не тянет лишнюю зависимость.

## 1. Исключение файлов по расширению (ядро библиотеки)

Цель: файлы с указанными расширениями (`.lock`, `.tmp`, `.db` и т.д.)
никогда не учитываются в размере и никогда не удаляются, независимо от
возраста и от того, насколько сильно не хватает места.

### 1.1 `config.go` — новое поле конфигурации

Добавить в структуру `CleaningConfig` (после блока `Optional settings`,
рядом с `RemoveEmptyDirs`):

```go
// ExcludeExtensions — список расширений файлов, которые НИКОГДА не
// учитываются при сканировании и никогда не удаляются, даже если они
// старше вычисленного порога threshold. Расширения сравниваются без
// учёта регистра, точка в начале необязательна (".tmp" и "tmp" — одно
// и то же после нормализации).
// Пример: []string{".lock", ".tmp", ".db"}
ExcludeExtensions []string

// excludeExtSet — нормализованный набор расширений для O(1)-проверки.
// Строится один раз в setDefaults(), чтобы не гонять по срезу
// ExcludeExtensions на каждый файл при сканировании миллионов файлов.
excludeExtSet map[string]struct{}
```

### 1.2 `config.go` — построение набора в `setDefaults()`

В функции `setDefaults()` (там же, где выставляются `TimeWindow`,
`Concurrency` и т.д.) добавить:

```go
// Строим набор расширений один раз при старте, а не на каждый файл.
// Нормализация: нижний регистр + гарантированная точка в начале, чтобы
// пользователь мог писать в YAML как ".tmp", так и "tmp" — не спорить
// об этом в конфиге.
if len(c.ExcludeExtensions) > 0 {
    c.excludeExtSet = make(map[string]struct{}, len(c.ExcludeExtensions))
    for _, ext := range c.ExcludeExtensions {
        ext = strings.ToLower(strings.TrimSpace(ext))
        if ext == "" {
            continue
        }
        if !strings.HasPrefix(ext, ".") {
            ext = "." + ext
        }
        c.excludeExtSet[ext] = struct{}{}
    }
}
```

Не забыть добавить `"strings"` в импорты `config.go`.

### 1.3 `config.go` — метод проверки

Добавить рядом с `ActualWorkerCount()`:

```go
// isExcluded сообщает, нужно ли пропустить файл целиком: не учитывать
// его в размере при сканировании и не удалять при очистке. Расширение
// берём через filepath.Ext, поэтому "backup.tar.gz" проверяется по
// ".gz", а не по ".tar.gz" — это осознанное упрощение (см. секцию 1.6
// про многосоставные расширения).
func (c *CleaningConfig) isExcluded(path string) bool {
    if len(c.excludeExtSet) == 0 {
        return false
    }
    ext := strings.ToLower(filepath.Ext(path))
    _, found := c.excludeExtSet[ext]
    return found
}
```

Добавить `"path/filepath"` в импорты `config.go`, если его там ещё нет.

### 1.4 `scanner.go` — пропуск при сканировании

Место: `processPath()`, ветка `else if info.Mode().IsRegular()`
(строка ~139 в текущем файле). Было:

```go
} else if info.Mode().IsRegular() {
    // Process regular file
    fi := fileInfo{
        path:      path,
        size:      info.Size(),
        blockSize: calculateBlockSize(info.Size(), s.blockSize),
        modTime:   info.ModTime(),
    }
    s.addFile(fi)
}
```

Стало:

```go
} else if info.Mode().IsRegular() {
    // Файлы с исключённым расширением вообще не попадают в timeSlots —
    // значит, они не участвуют в расчёте threshold (cleaner.go) и не
    // "занимают" объём, который планируется освободить. Это осознанное
    // решение: если такие файлы большие, MinFreeSpace может не
    // добраться до цели полностью — ожидаемое поведение, раз
    // пользователь явно попросил их не трогать.
    if s.config.isExcluded(path) {
        return nil
    }

    // Process regular file
    fi := fileInfo{
        path:      path,
        size:      info.Size(),
        blockSize: calculateBlockSize(info.Size(), s.blockSize),
        modTime:   info.ModTime(),
    }
    s.addFile(fi)
}
```

### 1.5 `deleter.go` — пропуск при удалении (критично!)

Место: `processPath()`, условие удаления (строка ~152). Было:

```go
} else if info.Mode().IsRegular() && info.ModTime().Before(threshold) {
    // Delete file if it's older than threshold.
    ...
```

Стало:

```go
} else if info.Mode().IsRegular() && info.ModTime().Before(threshold) {
    // ВАЖНО: deleter работает независимо от scanner (заново обходит
    // дерево, не переиспользует список файлов из фазы сканирования —
    // см. комментарий выше). Поэтому проверку исключения нужно
    // повторить и здесь: если убрать эту проверку, scanner корректно
    // не будет считать файл в размере, а deleter всё равно его снесёт,
    // потому что видит только ModTime и threshold, ничего не зная про
    // ExcludeExtensions.
    if d.config.isExcluded(path) {
        return nil
    }

    // Delete file if it's older than threshold.
    ...
```

Обе проверки (1.4 и 1.5) должны использовать один и тот же метод
`isExcluded` — не дублировать логику расширений в двух местах, иначе
они разъедутся при следующей правке.

### 1.6 Ограничение, которое стоит знать

`filepath.Ext("backup.tar.gz")` вернёт `.gz`, а не `.tar.gz`. Если
нужно исключать по составному расширению (`.tar.gz`, `.sql.gz`) —
`isExcluded` придётся доработать на `strings.HasSuffix(strings.ToLower(path), ext)`
вместо `filepath.Ext`. Для v1 достаточно простого варианта — фиксирую
это как известное ограничение, не блокер.

## 2. Dry-run (ядро библиотеки)

Цель: возможность прогнать всю логику (скан, расчёт threshold,
коллбэки) без реального `os.Remove`, чтобы CLI мог показать "что было
бы удалено" — честно, а не как сейчас в `examples/basic.go` (флаг
`-dry-run` там ничего не блокирует, только меняет текст в выводе).

### 2.1 `config.go` — новое поле

Рядом с `RemoveEmptyDirs`:

```go
// DryRun — если true, все шаги cleaner'а выполняются как обычно
// (скан, расчёт threshold, коллбэки OnFileDeleted/OnDirDeleted,
// статистика в отчёте), но реального os.Remove не происходит. Нужно
// для CLI-флага --dry-run: пользователь видит точный список файлов
// и итоговый объём, прежде чем разрешить настоящее удаление.
DryRun bool
```

### 2.2 `deleter.go` — пропуск `os.Remove` для файлов

Место: `processPath()`, внутри ветки удаления файла (строка ~157).
Было:

```go
size := info.Size()
blockSize := calculateBlockSize(size, d.blockSize)

if err := os.Remove(path); err != nil {
    return err
}
```

Стало:

```go
size := info.Size()
blockSize := calculateBlockSize(size, d.blockSize)

// В dry-run режиме файл физически не трогаем, но всю остальную
// бухгалтерию (счётчики, коллбэк OnFileDeleted, попадание директории
// в deletedDirs) прогоняем как при настоящем удалении — иначе отчёт
// и коллбэки в dry-run будут врать о том, что "было бы" удалено.
if !d.config.DryRun {
    if err := os.Remove(path); err != nil {
        return err
    }
}
```

### 2.3 `deleter.go` — пропуск `os.Remove` для пустых директорий

Место: `deleteEmptyDirRecursive()` (строка ~223). Было:

```go
if len(entries) == 0 {
    // Directory is empty, delete it
    if err := os.Remove(dir); err != nil {
        return err
    }

    (*deletedCount)++
```

Стало:

```go
if len(entries) == 0 {
    // Directory is empty, delete it (или сделать вид, если dry-run).
    // Здесь же кроется тонкость: в реальном режиме после os.Remove(dir)
    // родительская директория при следующем вызове ReadDir увидит на
    // одну запись меньше. В dry-run директория физически остаётся —
    // значит, "пустой" родитель на следующем уровне рекурсии
    // определяется неверно (запись всё ещё на месте). Это ограничение
    // dry-run для директорий: подсчёт deletedCount будет приблизительным
    // для вложенных пустых цепочек. Для файлов (2.2) эта проблема не
    // возникает, там каждый файл проверяется независимо от других.
    if !d.config.DryRun {
        if err := os.Remove(dir); err != nil {
            return err
        }
    }

    (*deletedCount)++
```

Если такое приближение не устраивает — можно завести отдельный
`dryRunDeletedDirs map[string]struct{}` и учитывать его при следующем
`ReadDir`, но для v1 это избыточно: dry-run в первую очередь нужен для
файлов (самое ценное — увидеть, что удалится и на сколько байт).

### 2.4 `cleaner.go` — менять не нужно

`CleanBackup()` вызывает `deleter.deleteFiles()` и
`deleter.deleteEmptyDirs()` без изменений — вся логика dry-run
инкапсулирована внутри `deleter.go`. Отчёт `CleaningReport` будет
корректно показывать "виртуальные" `DeletedFiles`/`DeletedSize`.

## 3. Многодиректорная поддержка + YAML-конфиг (новый слой, `cmd/backup-cleaner`)

Ядро (`gobackupcleaner`) не меняется в этой части — просто оборачивается
CLI-слоем, который на каждый target вызывает `cleaner.CleanBackup()`.

### 3.1 Новый файл `cmd/backup-cleaner/config.go`

```go
package main

import (
    "fmt"
    "os"
    "path/filepath"
    "time"

    "gopkg.in/yaml.v3"

    cleaner "github.com/ideamans/go-backup-cleaner"
)

// yamlConfig — корневая структура YAML-файла конфигурации.
// Поля Global* задают значения по умолчанию для всех targets, каждый
// target может их переопределить своими собственными.
type yamlConfig struct {
    Concurrency    int    `yaml:"concurrency"`
    MaxConcurrency int    `yaml:"max_concurrency"`
    TimeWindow     string `yaml:"time_window"` // строка вида "5m", парсим через time.ParseDuration
    Targets        []yamlTarget `yaml:"targets"`
}

// yamlTarget — правила очистки для одной директории. Указатели там,
// где нужно отличать "не задано" от "задано нулём" (например,
// MaxUsagePercent: 0 — валидное, но бессмысленное значение, поэтому
// используем *float64, а не float64).
type yamlTarget struct {
    Path string `yaml:"path"`

    MinFreeSpaceGB    *int64   `yaml:"min_free_space_gb"`
    MaxUsagePercent   *float64 `yaml:"max_usage_percent"`
    MaxSizeGB         *int64   `yaml:"max_size_gb"`

    TimeWindow      string `yaml:"time_window"`      // переопределение глобального, необязательно
    RemoveEmptyDirs *bool  `yaml:"remove_empty_dirs"` // *bool, чтобы отличить "не указано" от false
    DryRun          bool   `yaml:"dry_run"`

    ExcludeExtensions []string `yaml:"exclude_extensions"`
}

// loadYAMLConfig читает и парсит YAML-файл конфигурации по пути path.
func loadYAMLConfig(path string) (*yamlConfig, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return nil, fmt.Errorf("чтение конфига %s: %w", path, err)
    }

    var cfg yamlConfig
    if err := yaml.Unmarshal(data, &cfg); err != nil {
        return nil, fmt.Errorf("разбор YAML %s: %w", path, err)
    }

    if len(cfg.Targets) == 0 {
        return nil, fmt.Errorf("в конфиге %s не указано ни одного target", path)
    }

    return &cfg, nil
}

// resolvedTarget — то, что реально пойдёт в cleaner.CleanBackup:
// путь к директории + готовый CleaningConfig.
type resolvedTarget struct {
    Path   string
    Config cleaner.CleaningConfig
}

// buildTargets превращает распарсенный YAML в список задач на очистку,
// применяя глобальные настройки как дефолт и позволяя каждому target
// их переопределить. Возвращает также список ошибок валидации,
// которые НЕ прерывают весь запуск — битый target пропускается, чтобы
// один опечатанный путь не остановил очистку остальных директорий
// (инструмент рассчитан на запуск из cron без присмотра).
func buildTargets(cfg *yamlConfig) ([]resolvedTarget, []error) {
    globalWindow := 5 * time.Minute
    if cfg.TimeWindow != "" {
        if d, err := time.ParseDuration(cfg.TimeWindow); err == nil {
            globalWindow = d
        }
    }

    var targets []resolvedTarget
    var errs []error

    for i, t := range cfg.Targets {
        if t.Path == "" {
            errs = append(errs, fmt.Errorf("targets[%d]: не указан path", i))
            continue
        }

        info, err := os.Stat(t.Path)
        if err != nil || !info.IsDir() {
            errs = append(errs, fmt.Errorf("targets[%d] (%s): директория недоступна: %v", i, t.Path, err))
            continue
        }

        window := globalWindow
        if t.TimeWindow != "" {
            if d, err := time.ParseDuration(t.TimeWindow); err == nil {
                window = d
            } else {
                errs = append(errs, fmt.Errorf("targets[%d] (%s): некорректный time_window: %v", i, t.Path, err))
            }
        }

        removeEmptyDirs := true // дефолт библиотеки
        if t.RemoveEmptyDirs != nil {
            removeEmptyDirs = *t.RemoveEmptyDirs
        }

        conf := cleaner.CleaningConfig{
            MaxUsagePercent:   t.MaxUsagePercent,
            TimeWindow:        window,
            RemoveEmptyDirs:   removeEmptyDirs,
            Concurrency:       cfg.Concurrency,
            MaxConcurrency:    cfg.MaxConcurrency,
            DryRun:            t.DryRun,
            ExcludeExtensions: t.ExcludeExtensions,
        }

        // GB -> байты переводим тут, а не в CleaningConfig — библиотека
        // работает в байтах, GB — удобство только для человека,
        // читающего YAML.
        if t.MinFreeSpaceGB != nil {
            bytes := *t.MinFreeSpaceGB * 1024 * 1024 * 1024
            conf.MinFreeSpace = &bytes
        }
        if t.MaxSizeGB != nil {
            bytes := *t.MaxSizeGB * 1024 * 1024 * 1024
            conf.MaxSize = &bytes
        }

        if conf.MinFreeSpace == nil && conf.MaxUsagePercent == nil && conf.MaxSize == nil {
            errs = append(errs, fmt.Errorf("targets[%d] (%s): не задано ни одно из min_free_space_gb / max_usage_percent / max_size_gb", i, t.Path))
            continue
        }

        targets = append(targets, resolvedTarget{
            Path:   filepath.Clean(t.Path),
            Config: conf,
        })
    }

    return targets, errs
}
```

### 3.2 Новый файл `cmd/backup-cleaner/main.go`

```go
package main

import (
    "flag"
    "fmt"
    "log"
    "os"

    cleaner "github.com/ideamans/go-backup-cleaner"
)

func main() {
    configPath := flag.String("config", "", "путь к YAML-файлу конфигурации (обязателен)")
    dryRunOverride := flag.Bool("dry-run", false, "форсировать dry-run для ВСЕХ targets, игнорируя dry_run из YAML")
    verbose := flag.Bool("verbose", false, "подробный вывод по каждому файлу/директории")
    flag.Parse()

    if *configPath == "" {
        log.Fatal("нужен путь к конфигу: -config path/to/config.yaml")
    }

    cfg, err := loadYAMLConfig(*configPath)
    if err != nil {
        log.Fatal(err)
    }

    targets, errs := buildTargets(cfg)
    for _, e := range errs {
        // Ошибка валидации отдельного target не останавливает весь
        // запуск — только сообщается и пропускается (см. buildTargets).
        log.Printf("пропуск target: %v", e)
    }
    if len(targets) == 0 {
        log.Fatal("не осталось ни одного валидного target для очистки")
    }

    var totalFiles, totalDirs int
    var totalSize int64
    exitCode := 0

    for _, target := range targets {
        if *dryRunOverride {
            target.Config.DryRun = true
        }

        if *verbose {
            attachVerboseCallbacks(&target.Config, target.Path)
        }

        fmt.Printf("=== %s ===\n", target.Path)
        report, err := cleaner.CleanBackup(target.Path, target.Config)
        if err != nil {
            log.Printf("ошибка очистки %s: %v", target.Path, err)
            exitCode = 1
            continue
        }

        fmt.Printf("удалено файлов: %d, директорий: %d, освобождено: %s\n\n",
            report.DeletedFiles, report.DeletedDirs, formatBytes(report.DeletedSize))

        totalFiles += report.DeletedFiles
        totalDirs += report.DeletedDirs
        totalSize += report.DeletedSize
    }

    fmt.Printf("ИТОГО по всем targets: файлов %d, директорий %d, освобождено %s\n",
        totalFiles, totalDirs, formatBytes(totalSize))

    os.Exit(exitCode)
}
```

Функции `attachVerboseCallbacks` и `formatBytes` — переносятся почти
без изменений из `examples/basic.go` (там уже есть `formatBytes`,
коллбэки в `OnFileDeleted`/`OnDirDeleted`/`OnError`). Разница только в
том, что теперь коллбэки вешаются в цикле по нескольким targets, и в
сообщениях стоит добавить префикс с путём директории, чтобы в общем
логе было видно, к какому target относится строка:

```go
// attachVerboseCallbacks вешает коллбэки на config для подробного
// вывода. targetPath добавляется префиксом в лог, чтобы при обработке
// нескольких директорий за один запуск было понятно, где что удаляется.
func attachVerboseCallbacks(cfg *cleaner.CleaningConfig, targetPath string) {
    cfg.Callbacks = cleaner.Callbacks{
        OnFileDeleted: func(info cleaner.FileDeletedInfo) {
            verb := "удалён"
            if cfg.DryRun {
                verb = "был бы удалён"
            }
            fmt.Printf("[%s] %s: %s (%s)\n", targetPath, verb, info.Path, formatBytes(info.Size))
        },
        OnDirDeleted: func(info cleaner.DirDeletedInfo) {
            fmt.Printf("[%s] пустая директория удалена: %s\n", targetPath, info.Path)
        },
        OnError: func(info cleaner.ErrorInfo) {
            log.Printf("[%s] ошибка [%s]: %v", targetPath, info.Type, info.Error)
        },
    }
}
```

### 3.4 `go.mod` — новая зависимость

```bash
go get gopkg.in/yaml.v3
```

Так как `yaml.v3` импортируется только из `cmd/backup-cleaner`, а не из
корневого пакета `gobackupcleaner`, потребители библиотеки (`go get
github.com/ideamans/go-backup-cleaner` без CLI) её транзитивно не
получат — Go-модули тянут зависимости по графу импортов конкретного
пакета, а не всего репозитория.

## 4. Глубокое дерево директорий — изменений не требуется

`scanner.go` и `deleter.go` уже обходят дерево через worker pool с
fallback на синхронную рекурсию, если очередь задач (`buffer 100`)
заполнена — см. комментарии, добавленные в прошлой итерации. Глубина
дерева не проблема: горутины Go сами растягивают стек. Ничего в этом
пункте менять не нужно, просто держать в уме при выборе
`Concurrency`/`MaxConcurrency` в YAML.

## 5. Мелкая правка `scanner.go` — `sortTimeSlots`

Не обязательна для фич из ТЗ, но раз файл всё равно трогается в
пункте 1 (добавление проверки исключений) — заодно стоит поправить.

Место: `scanner.go`, функция `sortTimeSlots` (строка ~203). Было:

```go
func sortTimeSlots(slots []*timeSlot) {
    // Simple bubble sort for clarity (can be optimized if needed).
    n := len(slots)
    for i := 0; i < n-1; i++ {
        for j := 0; j < n-i-1; j++ {
            if slots[j].time.After(slots[j+1].time) {
                slots[j], slots[j+1] = slots[j+1], slots[j]
            }
        }
    }
}
```

Стало:

```go
func sortTimeSlots(slots []*timeSlot) {
    // Заменено с bubble sort (O(n^2)) на sort.Slice (O(n log n)).
    // При большом количестве временных слотов (мелкий TimeWindow или
    // ретеншн бэкапов на годы, много директорий за один запуск через
    // YAML-конфиг) старая реализация становится заметно медленнее.
    sort.Slice(slots, func(i, j int) bool {
        return slots[i].time.Before(slots[j].time)
    })
}
```

Добавить `"sort"` в импорты `scanner.go`.
