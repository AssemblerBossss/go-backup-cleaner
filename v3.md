# v3: новый режим — очистка по возрасту файлов (per-folder, без учёта диска)

## Задача

Вместо "держать диск в рамках capacity" — простое правило на папку:
"удалить в этой папке файлы старше N", плюс исключения по подпапкам
(на любой глубине) и по расширениям (уже есть, но см. баг ниже).

Это отдельный режим, ортогональный текущему (MinFreeSpace/MaxUsagePercent/MaxSize).
Диск вообще не должен опрашиваться в этом режиме — ни к чему не привязано,
кроме возраста файла.


## 0. Баг, который нужно починить в любом случае

`ExcludeExtensions` реально проверяется **только в scanner.go:146**
(`s.config.isExcluded(path)`) — это влияет исключительно на подсчёт размера
для capacity-режима (сколько всего "весит" дерево при расчёте targetSize).

В **deleter.go** (`processPath`, строка 156) проверки исключения нет вообще:

```go
} else if info.Mode().IsRegular() && info.ModTime().Before(threshold) {
    // удаляем без проверки isExcluded
```

Это значит: файл с расширением из `exclude_extensions`, если он старше
threshold, реально удаляется, просто не учитывается в оценке объёма.
Нужно чинить независимо от новой фичи — иначе `exclude_extensions` в новом
age-режиме тоже не будет защищать файлы от удаления.

**Фикс:** в deleter.go:156 добавить `&& !d.config.isExcluded(path)`.

### Новая функция `isExcludedDir`

```go
// isExcludedDir сообщает, нужно ли пропустить директорию целиком
// (не спускаться внутрь при сканировании/удалении) — сравнение идёт
// по имени директории (entry.Name()), а не по полному пути, поэтому
// совпадение срабатывает на любой глубине дерева.
func (c *CleaningConfig) isExcludedDir(name string) bool {
    if len(c.excludeDirSet) == 0 {
        return false
    }
    _, found := c.excludeDirSet[name]
    return found
}
```

Простое сравнение по имени (не glob) — соответствует запросу "не важно на
какой глубине". Если позже понадобятся шаблоны (`logs/2024/*`), это отдельное
расширение через `filepath.Match`, не обязательное сейчас.

### setDefaults() — добавить

```go
if len(c.ExcludeDirs) > 0 {
    c.excludeDirSet = make(map[string]struct{})
    for _, d := range c.ExcludeDirs {
        d = strings.TrimSpace(d)
        if d != "" {
            c.excludeDirSet[d] = struct{}{}
        }
    }
}
```

### validate() — изменить

```go
if c.MinFreeSpace == nil && c.MaxUsagePercent == nil && c.MaxSize == nil && c.MaxAge == nil {
    return ErrNoCapacitySpecified // либо завести отдельную ErrNoCriteriaSpecified
}

if c.MaxAge != nil && *c.MaxAge < 0 {
    return ErrInvalidConfig

```

Решить явно: **MaxAge исключает остальные три поля** (если задан MaxAge —
capacity-поля игнорируются) или можно их комбинировать. Для текущего
запроса ("правило на папку по возрасту") — проще и понятнее сделать
взаимоисключающим. Если MaxAge задан вместе с capacity-полями — можно либо
вернуть ErrInvalidConfig, либо просто игнорировать capacity-поля с логом.
Рекомендация: **вернуть ErrInvalidConfig**, чтобы не было тихого
неожиданного поведения.


## 2. scanner.go — пропуск исключённых директорий

`processPath` (scanner.go:121-143) сейчас рекурсирует во все поддиректории

if info.IsDir() {

## 4. cleaner.go — новая ветка режима "по возрасту"

Текущий `CleanBackup` (cleaner.go:9-...) целиком построен вокруг диска:
`GetDiskUsage` → `calculateTargetSize` → фаза сканирования с
time-slot-агрегацией → `calculateThreshold` → удаление. Для MaxAge всё это
не нужно: threshold известен сразу, без обращения к диску и без фазы 1
(`scanner.scan`), потому что `calculateThreshold` штатно нужен только чтобы
подобрать порог под целевой *объём*, а тут порог задан напрямую через
возраст.

### Изменение

В начале `CleanBackup`, после `config.setDefaults()`/`validate()`/проверки
существования директории, ветвление:

```go
if config.MaxAge != nil {
    return cleanByAge(dirPath, config, startTime)
}
// ...существующий capacity-путь без изменений
```

### Новая функция `cleanByAge`

```go
// cleanByAge удаляет файлы старше config.MaxAge, без обращения к
// состоянию диска — используется, когда задан MaxAge вместо
// MinFreeSpace/MaxUsagePercent/MaxSize.
func cleanByAge(dirPath string, config CleaningConfig, startTime time.Time) (CleaningReport, error) {
    blockSize, err := config.DiskInfo.GetBlockSize(dirPath)
    if err != nil {
        return CleaningReport{}, err
    }

    threshold := time.Now().Add(-*config.MaxAge)

    callSafe(config.Callbacks.OnStart, StartInfo{
        TargetDir: dirPath,
        // CurrentUsage не заполняется — в age-режиме состояние диска не опрашивается
    })

    deleteStartTime := time.Now()
    d := newDeleter(&config, blockSize)
    if err := d.deleteFiles(dirPath, threshold); err != nil {
        return CleaningReport{}, err
    }

    deletedDirs, _ := d.deleteEmptyDirs(dirPath) // см. v2.md — сигнатура меняется
    deleteDuration := time.Since(deleteStartTime)
    deletedFiles, deletedSize, deletedBlocks := d.getStats()

    callSafe(config.Callbacks.OnComplete, CompleteInfo{
        DeletedFiles:     deletedFiles,
        DeletedSize:      deletedSize,
        DeletedBlockSize: deletedBlocks,
        DeletedDirs:      deletedDirs,
        DeleteDuration:   deleteDuration,
    })

    return CleaningReport{
        DeletedFiles:     deletedFiles,
        DeletedSize:      deletedSize,
        DeletedBlockSize: deletedBlocks,
        DeletedDirs:      deletedDirs,
        DeleteDuration:   deleteDuration,
        TotalDuration:    time.Since(startTime),
        TimeThreshold:    threshold,
        BlockSize:        blockSize,
        // ScanDuration/ScannedFiles остаются нулевыми — фазы сканирования нет
    }, nil
}
```

### Что явно НЕ трогать / не удалять

`calculateTargetSize`, `calculateThreshold`, `calculateThresholdForMaxSize`,
`scanner.go` целиком, time-slot-агрегация — всё это остаётся как есть и
продолжает обслуживать существующий capacity-режим. Ничего из старого пути
не удаляется, MaxAge — параллельная ветка, не замена.

### Callbacks/Report — что учесть отдельно

`StartInfo.CurrentUsage`, `ScanCompleteInfo`, `DeleteStartInfo.Estimated*`
в age-режиме либо не вызываются вовсе (`OnScanComplete`, `OnDeleteStart` —
можно не звать, раз нет фазы оценки), либо вызываются с нулевыми/неполными
данными. Задокументировать в комментариях к `Callbacks`, что в MaxAge-режиме
`OnScanComplete`/`OnDeleteStart` не гарантированы — иначе пользователь
callback-ов будет удивлён, почему они не срабатывают.

### Проблема: time.ParseDuration не понимает дни/месяцы

`time.ParseDuration` поддерживает только ns/us/ms/s/m/h. "1 месяц" или "30d"
им не распарсить. Нужен небольшой враппер:

```go
// parseFlexibleDuration расширяет time.ParseDuration поддержкой суффиксов
// d (дни) и w (недели) — их нет в стандартной библиотеке. "Месяцы" сознательно
// не поддерживаются: месяц — величина переменной длины (28-31 день), явная
// неоднозначность; вместо max_age: "1mo" пользователь должен написать
// max_age: "30d" и понимать, что это приближение.
func parseFlexibleDuration(s string) (time.Duration, error) {
    if d, err := time.ParseDuration(s); err == nil {
        return d, nil
    }
    // fallback: число + суффикс d/w
    ...
}
```

Используется и в `TimeWindow`-парсинге (если тоже когда-нибудь понадобятся
дни), но по факту нужен прежде всего для `max_age`.

### buildTargets() — изменения

1. Парсить `t.MaxAge` через `parseFlexibleDuration`, класть в `conf.MaxAge`.
2. Прокинуть `conf.ExcludeDirs = t.ExcludeDirs`.
3. Обновить проверку "хотя бы один критерий задан" (сейчас

4. Явно решить и проверить в коде: если в YAML одновременно заданы

   уровне библиотеки, но лучше дать понятную ошибку уже на этапе
   `buildTargets`, с указанием номера target и пути).

## 8. Вернуть OnStart/OnScanComplete в подробный вывод CLI

### Контекст

В `examples/basic.go` (удалён) была секция `-verbose`, вешавшая на
`cleaner.Callbacks` шесть обработчиков: `OnStart`, `OnScanComplete`,
`OnFileDeleted`, `OnDirDeleted`, `OnError` (`OnDeleteStart` не
использовался). В текущем CLI (`cmd/backup-cleaner/main.go`, функция
`attachVerboseCallbacks`) остались только три последних —
`OnFileDeleted`/`OnDirDeleted`/`OnError`. `OnStart` и `OnScanComplete`
потерялись при переносе в CLI и нигде не подключены.

Нужно вернуть именно печать "что будет удаляться / что отсканировано",
в стиле остальных verbose-строк CLI (префикс `[путь-target]`, через
`formatBytes`, который уже есть в main.go).

### Куда писать

Файл: `cmd/backup-cleaner/main.go`, функция `attachVerboseCallbacks`
(строки ~76-92 на момент этого документа). Ничего выносить в отдельный
файл не обязательно — функция небольшая, добавляются ещё два case'а в тот
же `cleaner.Callbacks{...}`.

### Что дописать

```go
func attachVerboseCallbacks(cfg *cleaner.CleaningConfig, targetPath string) {
	cfg.Callbacks = cleaner.Callbacks{
		OnStart: func(info cleaner.StartInfo) {
			fmt.Printf("[%s] старт очистки\n", targetPath)
			// В age-режиме (config.MaxAge != nil) состояние диска не
			// опрашивается — CurrentUsage.Total будет нулевым, строку
			// про диск в этом случае печатать не нужно (см. cleanByAge
			// в cleaner.go и раздел 4 этого документа).
			if info.CurrentUsage.Total > 0 {
				fmt.Printf("[%s] диск: %.1f%% занято (%s из %s), цель: освободить %s\n",
					targetPath,
					info.CurrentUsage.UsedPercent,
					formatBytes(int64(info.CurrentUsage.Used)),
					formatBytes(int64(info.CurrentUsage.Total)),
					formatBytes(info.TargetSize))
			}
		},
		OnScanComplete: func(info cleaner.ScanCompleteInfo) {
			// В age-режиме фазы сканирования нет вообще (cleanByAge не
			// вызывает scanner), поэтому этот коллбэк для таких targets
			// не сработает — это ожидаемо, не баг.
			fmt.Printf("[%s] сканирование завершено: файлов %d, всего %s\n",
				targetPath, info.ScannedFiles, formatBytes(info.TotalSize))
			fmt.Printf("[%s] будут удалены файлы старше: %s\n",
				targetPath, info.TimeThreshold.Format("2006-01-02 15:04:05"))
		},
		OnFileDeleted: func(info cleaner.FileDeletedInfo) {
			verb := "удалён"
			if cfg.DryRun {
				verb = "был бы удалён"
			}
			fmt.Printf("[%s] %s: %s (%s)\n", targetPath, verb, info.Path, formatBytes(info.Size))
		},
		OnDirDeleted: func(info cleaner.DirDeletedInfo) {
			fmt.Printf("[%s] пустая директория удалена: %s\n", targetPath, info.Path)
		},
		OnError: func(info cleaner.ErrorInfo) {
			log.Printf("[%s] ошибка [%s]: %v", targetPath, info.Type, info.Error)
		},
	}
}
```

Отличия от `basic.go`:
- префикс `[%s]` с путём target — там был не нужен (один target на
  запуск), здесь нужен, т.к. CLI обрабатывает несколько targets за раз
  (см. main.go, цикл `for _, target := range targets`).
- `OnFileDeleted`/`OnDirDeleted`/`OnError` не трогаются — уже есть, просто
  дописываются `OnStart` и `OnScanComplete` в ту же структуру.
- явно закомментировано поведение в age-режиме (`MaxAge`), которого не
  было в `basic.go`, — чтобы не удивляться, почему для part of targets
  `OnScanComplete` молчит.

### Ничего больше менять не нужно

`OnDeleteStart` — как и в `basic.go`, его не подключаем, не несёт новой
информации поверх `OnScanComplete` для целей простого verbose-вывода.
